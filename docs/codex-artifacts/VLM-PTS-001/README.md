# VLM-PTS-001: 静态时间戳/帧桥接审计

> 本目录仅接收小型脱敏文本报告，**不接收视频、帧、模型、原始问题/答案、原始日志或本地敏感路径**。

## 目标

在不做视频解码、无GPU/模型调用、无下载、无环境更改的条件下，静态审核本地现有稀疏取帧、原生双帧/IMAGE12处理、timestamp生成与输入manifest的逻辑，明确它们是否能支持**源视频真实PTS、VFR、裁剪时间零点、跨版本证据区间桥接**。

这是工程/测量风险审查，不意味着允许 VLM-003 manifest 冻结或任何新GPU实验。

## 必要检查（只读）

1. 定位旧代码中 `frame_idx / fps` 估计时戳的具体函数和相关调用链；以安全相对路径、函数名及短摘要记载，不批量拷贝源代码。
2. 检查是否已有 PTS-aware 视频解码路径或可复用的依赖；仅检查静态代码、已安装包元数据与接口定义，不执行视频解码，也不作软件安装。
3. 分清 `video_pts`、`relative_clip_time`、`source_video_time`、`frame_index`、`fps`、`presentation_timebase`，列出现有manifest保存哪些字段，哪些没有。
4. 对 VFR、音画不同步、裁剪/转码版本漂移、同视频多索引、对齐容差、重复帧和多帧融合的潜在混淆，记录可复核的静态风险和后续验证要求。
5. 提出最小非侵入式修复**设计建议**和单元测试合同（输入/输出、不变量、失败码），**不要实现、修改或运行修复**；有权威文档就引用已有本地引用或链接，未知明确写UNKNOWN。
6. 检查任何已存在的测试/文档是否有PTS桥接断言；没有就写无证据，不可把静态函数声明当作真实帧时钟正确性的证明。

## 硬边界

- 本地研究资产、环境、锁、既有账本 **0修改**；GPU/模型QA/训练/评分前向 **0次**；视频解码、媒体下载 **0次**。
- 不反向解析或输出受限媒体、题目/标准答案；不创建正式新输入manifest，不提交代码补丁。
- 仅查与时间坐标相关的少量源码/静态manifest；每个文件只读取必要片段，报告中不能包含逐题原始身份或私人绝对路径。
- 如果源码不在当前允许目录或存在权限风险，停下，向用户报告BLOCKED；不要通过复制整个工作区解决。
- 与 VLM-002 的数据 G1 HOLD 相互独立：本任务**不允许**推翻许可、参考区间字段或来源独立性的未知。
